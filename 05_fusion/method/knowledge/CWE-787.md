# CWE-787: Out-of-bounds Write

## 1. Weakness Characteristics

The core issue is that code can write outside the valid bounds of the target object because index, offset, span, or destination size is not correctly enforced.

---

## 2. Expected Secure Behavior

Every write should be proven to stay within the writable extent of the exact target object for the entire written span.

---

## 3. Evidence Supporting TP

- Evidence: A reachable write uses an index, pointer, or offset that can point outside the target object.
  Explanation: A feasible invalid destination position directly supports a real out-of-bounds write.
- Evidence: The written span depends on length metadata, loop counts, or decoded values that are not checked against the remaining destination capacity.
  Explanation: Safety requires validating the full write range, not only the first byte or element.
- Evidence: Bounds are checked after the first write, on a different value, or against the wrong object.
  Explanation: An ineffective or mismatched guard does not make the reported write safe.
- Evidence: The destination pointer is advanced before write, but the code still reasons with total capacity instead of remaining capacity.
  Explanation: Offset-sensitive writes can overflow even when the original buffer is large enough.

---

## 4. Evidence Supporting FP

- Evidence: A dominating proof establishes both a valid starting position and sufficient remaining capacity for the complete write.
  Explanation: If the range proof holds on all paths, the warning does not describe a real defect.
- Evidence: The callee implementation or explicit API contract provides sufficient bounds guarantees for the reported write.
  Explanation: Some write sites look unsafe locally, but they are only safe when the implementation or contract actually enforces the required bound.
- Evidence: The target region is a view into a larger legal writable allocation, and the reported span stays within that larger extent.
  Explanation: Modeling only the local subobject can produce a false alarm.
- Evidence: The path that makes the write oversized cannot occur because earlier validation or normalization excludes it.
  Explanation: Unreachable bad states do not support TP.

---

## 5. Important Analysis Questions

1. Question: What exact bytes or elements can be written on the reported path?
   Why it matters: A warning is only valid if the full write span exceeds the true writable region.
2. Question: What is the real target object and remaining writable capacity at the write point?
   Why it matters: Offsetted destinations often have much less space than the total object size.
3. Question: Do the visible checks constrain the same object, offset, and write length?
   Why it matters: Nearby checks may be unrelated to the actual unsafe write.
4. Question: Does the write happen directly in the current function or inside a helper with its own safety semantics?
   Why it matters: Callee behavior can either confirm or refute the warning.
5. Question: Can arithmetic overflow, sign conversion, or unit mismatch enlarge the effective write range?
   Why it matters: Numeric transformations are common root causes of real out-of-bounds writes.

---

## 6. Common Misleading Patterns

- validating total capacity but not remaining capacity after offset
- guard after the first write
- helpers that silently truncate writes
- larger backing allocations hidden behind smaller local views
- write span widened by unit mismatch or numeric conversion

---

## 7. Required Context for Reliable Judgment

- target object identity and extent
- exact write span
- destination offsets and remaining capacity
- arithmetic and unit conversions
- callee semantics for write helpers

---

## 8. Static Analysis Warning Validation Notes

This specification is intended to assist static analysis warning validation.
The CWE category alone does not determine whether a warning is a real defect.
The final judgment should be based on the reported warning location, code path, data flow, control flow, API semantics, and project-specific behavior.
